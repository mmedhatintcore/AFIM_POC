# Spatie Media Library Integration

Use Spatie Media Library for **all** file uploads (event images, venue photos, organizer logos, etc.). **Always** use `MediaResource` for image responses — never return raw URL strings.

---

## Model Setup

Typical Sight Scape media collections:

- `Event`: `cover` (single), `gallery` (multiple)
- `Venue`: `photos` (multiple), `floor_plan` (single)
- `Organizer`: `logo` (single)
- `User`: `avatar` (single)

```php
use Spatie\MediaLibrary\HasMedia;
use Spatie\MediaLibrary\InteractsWithMedia;
use Spatie\MediaLibrary\MediaCollections\Models\Media;

class Event extends Model implements HasMedia
{
    use InteractsWithMedia;

    public function registerMediaCollections(): void
    {
        $this->addMediaCollection('cover')
            ->singleFile()
            ->acceptsMimeTypes(['image/jpeg', 'image/png', 'image/webp']);

        $this->addMediaCollection('gallery')
            ->acceptsMimeTypes(['image/jpeg', 'image/png', 'image/webp']);
    }

    public function registerMediaConversions(?Media $media = null): void
    {
        $this->addMediaConversion('thumbnail')
            ->width(300)
            ->height(200)
            ->sharpen(10)
            ->nonQueued();

        $this->addMediaConversion('preview')
            ->width(800)
            ->height(600)
            ->nonQueued();
    }
}
```

## Service Layer — Handling Uploads

```php
final class EventService
{
    public function updateCoverImage(Event $event, UploadedFile $file): Event
    {
        $event->addMedia($file)
            ->toMediaCollection('cover');

        return $event->fresh();
    }

    public function addGalleryImage(Event $event, UploadedFile $file, ?string $caption = null): Event
    {
        $event->addMedia($file)
            ->withCustomProperties(['caption' => $caption])
            ->toMediaCollection('gallery');

        return $event->fresh();
    }
}
```

## MediaResource (ALWAYS use for image responses)

```php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;

final class MediaResource extends JsonResource
{
    public function toArray($request): array
    {
        return [
            'id' => $this->id,
            'uuid' => $this->uuid,
            'name' => $this->name,
            'file_name' => $this->file_name,
            'mime_type' => $this->mime_type,
            'size' => $this->size,
            'url' => $this->getUrl(),
            'thumbnail_url' => $this->hasGeneratedConversion('thumbnail')
                ? $this->getUrl('thumbnail')
                : null,
            'preview_url' => $this->hasGeneratedConversion('preview')
                ? $this->getUrl('preview')
                : null,
            'custom_properties' => $this->custom_properties,
        ];
    }
}
```

## API Resource with Media

**IMPORTANT**: Always use `MediaResource` for images, never return URLs as strings.

```php
final class EventResource extends JsonResource
{
    public function toArray($request): array
    {
        return [
            'id' => $this->id,
            'title' => $this->getTranslation('title', app()->getLocale()),
            'starts_at' => $this->starts_at?->toIso8601String(),
            // CORRECT: Use MediaResource
            'cover_image' => $this->whenLoaded('media', function () {
                $media = $this->getFirstMedia('cover');
                return $media ? new MediaResource($media) : null;
            }),
            'gallery' => MediaResource::collection($this->getMedia('gallery')),
            // WRONG: Don't do this
            // 'cover_image' => $this->getFirstMediaUrl('cover'),
        ];
    }
}
```

## Filament with Spatie Media Library

**IMPORTANT**: Use `SpatieMediaLibraryFileUpload` and `SpatieMediaLibraryImageColumn` instead of Filament's native components.

```php
use Filament\Tables\Columns\SpatieMediaLibraryImageColumn;
use Filament\Forms\Components\SpatieMediaLibraryFileUpload;

// In Form
SpatieMediaLibraryFileUpload::make('cover')
    ->collection('cover')
    ->image()
    ->imageEditor()
    ->maxSize(4096)
    ->columnSpanFull(),

SpatieMediaLibraryFileUpload::make('gallery')
    ->collection('gallery')
    ->multiple()
    ->image()
    ->maxFiles(10)
    ->maxSize(4096),

// In Table
SpatieMediaLibraryImageColumn::make('cover')
    ->collection('cover')
    ->conversion('thumbnail')
    ->square(),
```

## Queued vs Non-Queued Conversions

- **Non-queued** — fast, synchronous. Use for small uploads (avatars, logos) where the user expects the thumbnail immediately.
- **Queued** (default in Spatie) — generated by the `ProcessMediaJob` worker. Use for galleries, event covers, anything large. **Requires the queue worker to be running** (`php artisan queue:work`) — otherwise `thumbnail_url` stays `null`.

```php
$this->addMediaConversion('thumbnail')->width(300)->height(200); // queued
$this->addMediaConversion('avatar')->width(200)->height(200)->nonQueued(); // sync
```

Always gate conversion URLs with `hasGeneratedConversion('name')` in `MediaResource` so the frontend can fall back gracefully while a conversion is still processing.

## Fallback URLs

For collections that may be empty (e.g. `User` avatars when the user hasn't uploaded), register a fallback:

```php
$this->addMediaCollection('avatar')
    ->singleFile()
    ->useFallbackUrl(asset('images/default-avatar.png'))
    ->useFallbackPath(public_path('images/default-avatar.png'));
```

The API still returns `null` from `getFirstMedia('avatar')`, so the frontend handles the empty case via the `MediaResource` being `null`. The fallback URL is for admin/Filament display.

## Storage Disks

Production uses S3 (or S3-compatible like Cloudflare R2). Configure per collection:

```php
$this->addMediaCollection('cover')
    ->singleFile()
    ->useDisk('s3');
```

The default disk for media is set in `config/media-library.php` → `disk_name`. Keep local/test runs on the `public` disk and production on `s3` via env.

---

## Deleting Media

Never delete files directly from the filesystem. Use Spatie's API so the database row is cleaned up too:

```php
$event->getFirstMedia('cover')?->delete();                // single
$event->clearMediaCollection('gallery');                  // whole collection
$event->clearMediaCollectionExcept('gallery', [$keep]);   // all but one
```

If the owning model is soft-deleted, media is kept by default (good — lets restores work). Hard-delete cascades media via the trait.

## Custom Properties (Captions, Alt Text, Ordering)

Store per-file metadata in `custom_properties` instead of a separate table:

```php
$event->addMedia($file)
    ->withCustomProperties([
        'caption_en' => 'Main stage at sunset',
        'caption_ar' => 'المنصة الرئيسية عند غروب الشمس',
        'alt_en'     => 'Outdoor concert stage',
        'alt_ar'     => 'منصة حفلة خارجية',
        'order'      => 1,
    ])
    ->toMediaCollection('gallery');
```

`MediaResource` already serializes `custom_properties`. For accessibility, always provide both Arabic and English alt text — frontend picks by locale.

## PHP Upload Limits

If uploads silently fail for files around a few MB, it's almost always PHP config, not the app. Check and raise in `php.ini` / the web server:

```ini
upload_max_filesize = 20M
post_max_size       = 24M
memory_limit        = 256M
```

Filament's `->maxSize(4096)` is KB — align it with the server limit. On Laravel Sail / Valet, edit `.user.ini` or the Sail PHP FPM config.

## Responsive Images (Optional)

For public event covers, enable responsive images so the frontend gets a `srcset`:

```php
$this->addMediaCollection('cover')
    ->singleFile()
    ->withResponsiveImages();
```

Then expose via `$media->getResponsiveImageUrls('cover')` inside a dedicated resource field. Don't enable globally — it inflates storage.

---

## What NOT to store in Media Library

- **Receipts / invoices / PDFs** that need ZATCA archival — these belong in a dedicated `documents` table with integrity hashes.
- **Secrets or user-uploaded sensitive docs** (national IDs for vendor KYC) — use a private disk with signed URLs and a retention policy, not the default public media flow.
- **Generated tickets / QR codes** — regenerate on demand or cache at a CDN edge; don't persist per-ticket images in the media table.
